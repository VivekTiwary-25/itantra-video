## Goal
Vivek is re-recording all narration lines (N1, N2, N2a-N2f, N3, N5, N5a-N5b, N6, N7, N7a-N7d) into `local/narration_vivek/<id>.wav` on vivek-pc. The lead runs ONE command when they land; write it.

## Details
`python film/narration/prep_v4.py [--only N2a,N2b] [--no-copy]` (runs on vivek-pc outside any sandbox):
1. For each line id in `film/common/narration_v4.json` with a file `local/narration_vivek/<id>.wav` (also accept .mp3/.m4a, case-insensitive names like `n2a.wav`): run the existing cleaning of `film/narration/prep.py` on it (read prep.py; reuse its functions; if prep.py rejects a take as clipped, fall back to the 30 Sep approach: limiter + static gain, and say so), output `RENDERS:narration/v4/<id>.wav` (48 kHz mono, -18 LUFS, never time-stretched, never cut mid-word: trim only leading/trailing silence with 80 ms margins).
2. Transcribe each output with faster-whisper (`local/models/faster-whisper-medium.en`, CPU int8, word timestamps; decode audio with ffmpeg to a numpy array: PyAV is broken on that PC), and write into `film/common/narration_v4.json`: `duration` (s, 3 decimals), `text` (the transcript; fix casing of iTantra, chmod 777, SIH26173, Bluetooth LE, Google Tink), `words` (word timings), `status: "real"`.
3. Unless `--no-copy`: copy the new wavs to the render machines' `RENDERS:narration/v4/` over SSH with scp, hosts and clone paths from `local/swarm/itantra-video.json` (machines utkarsh-pc and yash-pc; skip unreachable ones with a warning; timeouts on every ssh/scp).
4. Print a table: id, duration vs old placeholder, text.
5. `README_v4.md`: the command and what to do after (rebuild segments whose lines changed: s2a N1; s2b N2-N3; s3 N5-N6; s4 N7-N7d).
Test on synthetic wavs (e.g. ffmpeg sine bursts named N2a.wav) in a temp folder on your laptop with `--no-copy` and a `--manifest` override so the real manifest isn't touched; no ASR model needed for the test if it's absent (skip transcription with a warning).
