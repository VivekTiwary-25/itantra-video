## Goal
A small always-on watcher on vivek-pc that tells the lead (and Vivek, via ntfy) when a worker sits idle while film work is waiting. About 15 minutes of work. Code only: you do not install or run it on vivek-pc; the lead does.

## Details
Write `tools/idle_watcher.py` (Python 3.12 stdlib only) and `tools/install-idle-watcher.ps1`.

`idle_watcher.py --clone <path> --out <file> [--loop] [--interval 120]`:
1. Every `--interval` seconds (default 120): `git -C <clone> pull --ff-only -q` (the clone is a dedicated read-only clone, never written by anything else; on a pull error, log it and keep going with the old state).
2. Read `machines/registry.json`, every `machines/<m>/heartbeat.json`, `queue/<worker>/*.md`, `queue/lane-*/*.md` (front matter: id, worker, lane, cli, machine, depends_on), `results/<id>/STARTED.json`, `results/<id>/REPORT.md` (status), `reviews/<id>.md` (verdict). Same rules as PROTOCOL.md section 4: a task is *ready* when it has no STARTED.json, is not dropped, and every depends_on has REPORT done + review accepted. Running = STARTED without REPORT.
3. Per worker with `queue: true` in the registry (skip `codex-yojitth`, it is out): busy/idle (heartbeat `status`, `current_task`), since when (keep a small state file next to `--out`, `<out>.state.json`, recording when each worker's status last changed; on first run use the heartbeat time), heartbeat age, ready tasks in its own queue, and ready pool tasks it could take (lane pools; respect `cli:` and `machine:`).
4. Write `--out` (markdown, overwrite atomically: write tmp then replace). Top of file: an **ALERTS** block (or "No alerts"), then a table: worker | machine | busy/idle | since | current task | own ready | pool ready | heartbeat age. Then "Ready tasks" (id, worker/pool, title) and "Running" (id, worker, started). Times in IST (UTC+5:30), HH:MM.
5. Alerts:
   - idle > 10 min while the file `local/watcher-active` exists in the lead folder (pass it as `--active-flag <path>`; it means "the film has unfinished work") OR while any ready task exists that this worker could take;
   - heartbeat older than 15 min (stale).
6. ntfy: topic from the environment variable literally named `Ntfy Topic` (with the space; read `os.environ`, and if missing on Windows read it from `HKCU\Environment` via `winreg`). Send by running `powershell -NoProfile -Command "Invoke-RestMethod -Method Post -Uri ('https://ntfy.sh/' + $env:T) -Body $env:B"` with T and B passed through the child's environment (never on the command line). Message short, no paths or private content, e.g. `iTantra: codex-f2 idle 12 min, 3 tasks ready` or `iTantra: yash-pc heartbeat stale 18 min`. At most one ping per worker per alert episode, repeat after 30 min if still true. `--no-ntfy` flag for testing. `--test-ping` sends one "iTantra watcher: test ping" and exits.
7. Never crash the loop: catch and log every exception to `<out>.log` (keep it under 1 MB, rotate once).

`install-idle-watcher.ps1 -Repo <lead folder> -Clone <watch clone path>`: clone the GitHub repo (origin URL of `-Repo`) into `-Clone` if missing; create `local/watcher-active` in `-Repo`; register a Scheduled Task `itantra-idle-watcher` for the current user, trigger At logon, action `pythonw.exe <Repo>\tools\idle_watcher.py --loop --clone <Clone> --out <Repo>\local\worker-status.md --active-flag <Repo>\local\watcher-active` (find pythonw next to `python` on PATH), restart on failure (3 times, 1 min), no time limit, hidden; then start it now. `-Uninstall` removes the task. Do not change execution policy.

Test it yourself on your clone with `--no-ntfy` once (single pass, no `--loop`), and put that sample output in `results/F0001/sample-status.md` (it has no private data).
